# Social preview image — design

**Date:** 2026-09-06
**Status:** approved

## Goal

A 1280×640 image for the repository's GitHub social preview, so a link to
`ozykhan/iina-airplay` in a chat, a tweet or a search result carries something
better than a cropped README screenshot. One job: say what this is, in the
half-second someone looks at a link card.

## Decisions taken

| Question       | Decision                                                             | Why                                                                                                                                            |
| -------------- | -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Subject        | The AirPlay symbol, drawn to Apple's proportions                     | The one glyph that says "this casts to a TV" with no reading required                                                                          |
| IINA's logo    | Not used                                                             | Considered and rejected mid-design. The association is carried by material — IINA's gradient and its violet — rather than by borrowing its mark |
| Framing        | Whole symbol in frame, nothing cropped                               | Three cropped variants were tried; the symbol stops reading as AirPlay the moment the screen is cut, which defeats the point                    |
| Format         | Hand-authored SVG as the source, PNG rendered from it                | The SVG stays editable and diffable; GitHub needs a raster                                                                                     |
| Build step     | None. Both files committed, PNG regenerated by hand                  | Same treatment as `docs/demo.mp4`: a committed asset, not a build product                                                                       |
| Ground         | Near-black `#0B0B0D`                                                 | Matches IINA's own icon and the landing page's dark mode; link cards sit on white far more often than on black                                  |

## The mark

Proportions measured off Apple's own symbol rather than eyeballed:

| Property                        | Value        |
| ------------------------------- | ------------ |
| Screen aspect                   | 16:9         |
| Apex depth into the screen      | 43% of its height |
| Triangle height ÷ base width    | 0.67         |
| Base below the screen's rule    | 22% of the screen height |
| Rule weight                     | 4.5% of the screen width |

As drawn: a 486×274 screen at (742, 153), rule 28px, corner radius 68px. The
triangle is `M985 270 L1147 487 L823 487 Z`, stroked 18px with a round join —
which is what rounds its corners. Rounded corners are the one deliberate
departure from the reference, which draws them square.

Placing the screen at y=153 centres the mark on the canvas *once the triangle is
counted*; the triangle hangs 22% of the screen height below the rule, so
centring the screen alone sits the whole mark visibly high.

**The break in the bottom rule** is the detail that makes it read as AirPlay
rather than as a triangle in a box. It is cut by a mask (`#cut`) holding a copy
of the triangle dilated 26px on every side, so the gap follows the triangle's
edges exactly, stays even the whole way along, and stays correct if the triangle
is ever moved or resized. Drawing the rule as an open path with hand-placed
endpoints would have to be re-derived by hand on any change.

## Colour

Sampled from `/Applications/IINA.app/Contents/Resources/AppIcon.icns`, not from
memory:

| Role                       | Value                              |
| -------------------------- | ---------------------------------- |
| IINA's play triangle       | `#006BC8` → `#009DFE` → `#00C0D7`  |
| IINA's pause bars          | `#673AF6` → `#4656FF`              |
| IINA's icon body           | `#4A4A4A` → `#242424`              |

The screen's rule runs cyan→blue from its top-left; the triangle runs the same
gradient the other way, so the two meet in the middle. Blue ambient light sits
behind the mark and violet low and left, which is the only place IINA's violet
appears now that its pause bars are gone.

## Type

Left column, system font throughout (`-apple-system` / SF Pro):

- `iina-airplay` — 92px, weight 700, letter-spacing −4, `#F5F5F7`
- `Cast what IINA is playing / straight to your Apple TV.` — 34px, `#A1A1A6`,
  two lines. Taken verbatim from the README's opening line
- `No mirroring · no re-encode / IINA stays the remote` — 23px, weight 500,
  `#6E6E73`, under a 72px rule

## Files

```
assets/
  social-preview.svg    the source, hand-edited
  social-preview.png    1280×640, ~300 KB, rendered from the SVG
```

Regenerate the PNG after editing the SVG:

```sh
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless \
  --disable-gpu --hide-scrollbars --force-device-scale-factor=1 \
  --window-size=1280,640 --screenshot=assets/social-preview.png \
  "$PWD/assets/social-preview.svg"
```

Chrome is used because it is already on the machine and renders `-apple-system`
correctly; `rsvg-convert` substitutes a different face. The SVG carries explicit
`width`/`height` so the screenshot lands at exactly 1280×640.

Note that the render command cannot be quoted in a comment inside the SVG: XML
forbids a double hyphen inside a comment, and every flag begins with one. That
is why it lives here.

## Installing it

Uploading the image is a repository setting and cannot be scripted through the
API — it is a manual step:

**Settings → General → Social preview → Edit → Upload an image**, then pick
`assets/social-preview.png`.

GitHub's stated bounds are 1280×640 and under 1 MB; this is 1280×640 and ~300 KB.

## Deliberately not done

- **`docs/index.html`'s `og:image` is unchanged.** It still points at
  `demo-poster.jpg`. For the landing page a real screenshot of the product is
  arguably the better card, so switching it is a separate call, not a
  consequence of this one.
- **No README change.** The README's demo GIF is doing a different job.
- **No Makefile target.** One hand-run command for an asset that changes almost
  never does not earn a build rule.
